## What is an AI Agent Harness?

An **AI Agent Harness** is the runtime environment, benchmarking framework, evaluation testbed, or execution sandbox that provides:
1. **Task Environments & Datasets**: Realistic scenarios (codebases, browser interfaces, terminal shells, APIs).
2. **Execution Runtimes**: Isolated sandboxes (Docker, WebContainers, microVMs) to safely run agent actions.
3. **Observation & Tooling Interfaces**: Standardized protocols (e.g., Model Context Protocol / MCP, tool-calling APIs).
4. **Scoring & Verification**: Deterministic or LLM-judged metrics to validate agent completion and test against regressions.

This repository dynamically indexes, categorizes, and tracks open source harnesses across the GitHub ecosystem using **GitHub Topics**.

## How It Works

This repository is maintained autonomously by a GitHub Actions workflow:

1. **Discovery**: Queries the GitHub Search API on a scheduled cron and on demand using targeted topic queries (`topic:agent-harness`, `topic:eval-harness`, `topic:swe-bench`, etc.).
2. **Validation**: Filters candidates strictly for open-source licenses (OSI-approved SPDX keys), non-archived status, and minimum star thresholds.
3. **Topic Grouping**: Clusters repositories into functional harness categories based on their defined GitHub topics and indexes all raw tags.
4. **Autonomous Publishing**: Generates `README.md` and machine-readable `data/harnesses.json`, committing updates automatically if changes are detected.

## Contributing

Want to add your AI agent harness or testbed to this list?

### Method 1: Tag Your GitHub Repository (Automatic)
Add relevant topics to your GitHub repository (under the repo's "About" section):
- Core topics: `agent-harness`, `eval-harness`, `swe-bench`, `browser-use`, `agent-benchmark`, `agent-sandbox`.
- Ensure your repository has an OSI-approved open source license (`MIT`, `Apache-2.0`, `BSD`, `GPL`, etc.).
The automated workflow will pick up your repository on its next run!

### Method 2: Submit a Pull Request
Add your repository to `seed_repos` in [`config/settings.yaml`](config/settings.yaml):
```yaml
seed_repos:
  - "your-org/your-agent-harness"
```
Or propose a new topic category in [`config/topics.yaml`](config/topics.yaml).
